# AI 辅助整理 · V0.5.1

## 少量体验步骤

打开 <http://127.0.0.1:5173>。旧数据会先提示下载保护备份，再升级；不要清除浏览器数据。

1. 导入资料并核对提取结果；普通笔记没有明确问答时可“仅保存资料”。进入“AI 辅助整理”。
2. 页面先显示本机服务及所选模型是否可用。主动启用辅助，选择学习目标，检查原文范围，再同意本次发送。
3. 按来源分组查看候选，优先核对风险提示。可筛选来源不足、重复、已修改；比较重复答案。题干与要点可编辑、增删、合并，修改自动保存。
4. 可以刷新、关闭重开；从“AI整理草稿”继续。密钥不保存，继续模型调用需重新输入及主动同意。
5. 仅选择已经核对的候选，确认原文及必要内容完整后批量保存，点击“开始正式复习”。未确认草稿不影响题库或FSRS。
6. “AI整理草稿→查看真实模型评测与限制”可看10份固定材料的所有结果，包括错误，不能只看生成数量。

没有AI时，原有编号题库导入、PDF/OCR、手工制卡、复习和统计正常工作。已有题目详情可建议评分要点/题干；**既有标准答案始终不被AI改写**。

## 本机模型与启动

本轮已有 CPU Qwen2.5-1.5B-Instruct Q4_K_M：文件1117320736字节，约1.04GiB，推理可能占用数GiB内存。接口`http://127.0.0.1:8089/v1`，模型名`qwen2.5-1.5b-instruct`，无需密钥。小模型质量有限，不是推荐的最终教学模型。

- 当前5173体验地址由新的会话启动器提供。没有自动启动模型、安装系统软件或设置开机服务。
- 启动器未连接时，网页会明确说明浏览器不能自行安装/启动。Ubuntu项目目录内的“打开RecallLab.sh”可启动网页与按需入口；若文件管理器询问，选择运行。它使用已有项目依赖构建产品，不下载模型或安装软件。也可继续使用已有Ollama服务。
- 已找到运行文件时，勾选“同意本次按需启动…”再点击启动。加载后重新检测；只停止本启动器自己启动的模型。关闭启动器会结束它启动的模型，不停止其他服务。
- 现有权重原本位于`/tmp`，可能被系统清理。网页可在明确同意空间占用后把已有模型和运行器保存到项目忽略目录`.local-ai/installed`，约1.09GiB；这是本机复制，不联网。先检查保存后至少2GiB余量、校验模型，再原子安装，失败保留原件。**本机已根据用户授权选择更节省空间的方式完成保存：权重同分区硬链接保管，仅复制约52MiB运行器；没有再复制GB权重。具体资源检查、路径及行为见[本机决定记录](LOCAL_MODEL_DECISION_V051.md)。**
- 缺文件/模型时明确提示，不假装已经安装；本轮没有全新设备的自动模型下载器。Ubuntu现有运行器经过实测；Windows/macOS可使用Ollama/兼容服务，但未做原生安装验收。

启动器只允许回环地址、同源授权和固定模型参数，不运行任意命令。已有运行器的临时RUNPATH依赖通过自身动态库目录处理；重新定位运行器的真实启动与完整网页闭环已测试，未把小文件模拟测试当成真实模型验收。

## 隐私与数据

Mock明确只是模拟，不调用模型。兼容接口支持本机和主动选择的外部HTTPS服务；Ollama仅限本机。状态检测不发送正文，也不自动探测外部服务。生成只发送选择的原文、题干及任务，不发送学习历史、其他文件或整个数据库，不偷偷换服务。

密钥只在页面内存，关闭辅助清除，不写IndexedDB、草稿、备份或Git。外部服务的留存/CORS由该服务控制；网页不是密钥保险箱，不适合组织共享密钥。

草稿包含原文及编辑结果，保存在当前浏览器，**完整备份包含草稿**。可在草稿清单明确删除。每份4MiB，总计12MiB/20份，来源正文去重保存；全文快照过大时可能超限，仅缩小页码不一定足够，需要拆分资料。保存失败会提示、保留当前页面并提供导出，不宣称已经持久保存。

数据库正式升级至v6，保留v1—v5和原始历史/调度；升级前下载保护备份，事务内保留v5副本，失败回滚。恢复旧备份仍兼容；恢复会更新草稿版本令牌，旧页面不能覆盖恢复结果。旧版程序不支持降级编辑，不把数据库版本号当成旧客户端写锁。

## 来源、内容与确认

原文、引用位置、模型原始题干/答案/要点、当前编辑与最终确认分开显示。原文背诵答案直接取真实原文切片，不能用模型改写替换。片段引用为试验方案：模型给片段编号，程序只从本次原文还原，保留原始编号，不相信模型自报页码。

引用必须唯一定位，只允许保守空白排版还原，不改文字、标点或英文词界。引用匹配不等于语义支持、完整性或正确率；OCR仍需对照原件。来源全文/页面信息或既有题目修订变化后，草稿只能查看、导出，不能直接确认。跨标签页冲突保留当前输入，不静默覆盖；可导出或明确载入最新版本。

确认整批成功或全部回滚，同时保存收据及剩余草稿，避免重复提交。已确认条目不再出现在待审列表；部分确认后如需继续未生成段落，要先完成/保留剩余内容，再明确新建批次。改动题干、目标或必要要点会建立新学习状态，旧事件和修订继续保留。

模型没有文件/数据库/联网工具，资料内指令不能执行操作。已识别的操作指令和答案开头复制会在确认事务中拒绝；规则不能识别所有恶意或语义错误，人工完整性确认不可省略。

## 当前实测和限制

[完整评测](evaluations/V051_MODEL_REPORT.md)：10份固定公开材料各跑一次。逐字方案12候选/10引用定位；片段方案13/13，但3条要点引用不合要求，仍有“可能”被写成“是”、要点仅“第一/第二”等错误。**没有证明片段方案总体更好，也没有验证个人学习效果。**

私人69题资料仍可规则导入；本机AI的7次题干请求返回6候选/6引用有效，仅2条通过原有题干检查，1次超时；长答案仅1个必需要点，未证明完整，未自动确认私人资料。

没有真实用户确认率、修改量或可用题准备时间；生成耗时和批次墙钟时间不能当作有效学习/准备时间。没有AI自动判分、FSRS自动评分、Agent、账户或云同步。真实Ollama/收费接口和Windows/macOS未实际运行；协议/错误路径的模拟测试另列。

取消、超时、模型断开或非法输出保留此前候选；未确认内容不写题库。每批10万字符/50候选，每段3500字符/8候选，长文可按范围继续。完整JSON恢复仍限50MiB：实测2000题（其中1000条含AI来源）、10000事件与20草稿约44.4MiB，恢复一致；更长原文/更多修订可超过上限，不能保证任意规模。导出会显示体积和超限提醒，勿因此清空原浏览器数据。
